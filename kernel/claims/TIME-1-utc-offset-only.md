# TIME-1: Persisted and domain time is UTC-anchored, offset-aware, and nothing else

**Statement.** All time values in domain types, contracts, and persistence are UTC-anchored offset-aware types. That phrase fuses two properties and the claim names them separately, because a stack can supply one without the other and the claim is unsatisfiable as written on such a stack unless it says which is which. **Unambiguity**: the value denotes exactly one instant, so it orders, compares, and persists without reference to anything else. This is what buys the claim its harm paragraph, since every failure listed there is a value that means two times. **Offset retention**: the value keeps the offset it was written in, so the reading that produced it is reconstructible without a second lookup. This is what buys the display edge its input and an incident reader the time the user actually saw. Local wall-clock types (naive datetimes) have neither and never appear in those layers. A type with unambiguity and no offset retention (an epoch instant, which discards the originating offset at parse and offers no accessor for it) is neither the forbidden shape nor the permitted one, and an edition realizing this claim on such a type states which property it has and where the other one is carried, rather than reporting the ban satisfied. Conversion to a user's local time happens at the display edge, using the timezone stored on the authenticated principal; an operation that requires a timezone refuses when it is absent rather than guessing (DATA-5). Elapsed time is measured, never computed from wall clocks: a duration comes from the monotonic source through one clock seam, not by subtracting two wall-clock readings, because the wall clock steps under NTP correction and the difference across a step is not a duration.

**Harm.** Naive datetimes are ambiguous at every DST transition and every cross-region deployment: double bookings, off-by-hours scheduling, unorderable audit trails. Both source systems converged on this independently, which is what "kernel" means.

**Enforcement.**
- Mechanism class: a structural test over every layer the statement names (domain, contracts, application, persistence) rejecting declarations of forbidden time types, by whatever means that stack exposes its declarations. The monotonic-durations extension adds a lint banning wall-clock-delta idioms (subtracting two now-readings) outside the clock seam, which exposes the monotonic source.
- Completeness obligation: **when**, at build time over the declared layers, and the set of layers is derived from a rule the test can check rather than from a hand-written list, because a hand-written list omits a layer silently and the omission looks exactly like coverage: measured, a naive time type on a public type in an unlisted layer left the whole suite green while the identical type one layer over turned it red. **Closure**, into nullable, array, collection, and generic shapes, and through the members of any type a listed layer declares, since a forbidden time type one level inside a declared record is the same ambiguous value as one at the top. **Remedy**, a forbidden declaration fails the build; a layer that exists and is not in the enumeration fails the build too, which is the part that makes the closure checkable rather than asserted.

**Weakening notes.** Date-only and time-only domain concepts (a birth date, a clinic opening hour) are legitimately zoneless; the edition uses `DateOnly`/`TimeOnly` for those, which the scan permits, so the ban stays crisp: what is forbidden is ambiguous instants, not calendar concepts.

The permitted shape is still insufficient for a category the claim does not yet name. `DateTimeOffset` records a fixed offset, not a zone. For a past instant that is enough; for a scheduled *future* local event (an appointment, a medication time) it is not, because the zone's DST rules can change between now and the event (Australian jurisdictions have changed them within living memory) and a stored offset silently becomes wrong. A future local event stores wall time plus the IANA zone id and resolves to an instant at read. The v1 exemplar has no future-dated scheduling, so this is recorded as the rule the first scheduling slice adopts, not something the current scan enforces.
